# 运动卡健康检查与断电恢复

## 在线状态

`opened` 只表示 SDK 曾打开连接，不能单独证明设备在线。非视觉物理点的
`online` 现在由最近成功轮询、板卡采样时钟进度和当前会话有效性共同决定。
视觉和虚拟点继续使用各自状态。轴失能属于运动不可用，不等同于整张卡通信离线。

默认配置（runtime.ini 的 `[card]`）：

| 配置 | 默认值 | 作用 |
|---|---:|---|
| healthProbeIntervalMs | 1000 | 使用公开 `MC_GetSts` 接口读取板卡采样时钟 |
| healthTimeoutMs | 5000 | 轮询或采样时钟无进展的有效期 |
| pollFailureTolerance | 3 | 连续读取失败后销毁旧连接并重连的阈值 |
| reconnectIntervalSec | 5 | 后台连接重试间隔 |

要求 `0 < healthProbeIntervalMs < healthTimeoutMs`。首次读失败即撤销在线状态，
不必等满三次；下一次有效检查可以恢复在线。独立看门狗每 100 ms 检查过期，
不调用 SDK，也不等待运动锁。状态变化唤醒 MQTT 心跳线程，在 MQTT 可用时及时
上报，无需等待默认的 10 秒周期。进程 `status=ALIVE` 与设备点 `online=false`
可以同时成立，表示 Adapter 活着但硬件离线。

首次打开板卡也在后台执行，不阻塞 MQTT 注册和离线心跳。SDK 调用失败、时钟
倒退、时钟冻结和轮询阻塞均有离线保护。时钟倒退包括计数回绕，采取保守重连。
MC_GetSts 的实际采样时钟行为需要在部署设备和其 DLL 版本上做一次断电验证；
成功绑定 DLL 导出不能替代硬件验证，也不能检测全部发生在采样间隙的短暂变化。

## 指令与恢复

- 失效会话拒绝新指令；排队指令进入分发器后再次检查会话，避免跨重连执行。
- 移动、点动和回零下发前读取使能位及相关故障；轴失能返回失败，不自动清报警。
- 重连执行原有完整初始化（含三轴使能），并新增使能回读检查及首次健康检查。
- 会话失效后的迟到完成不能报成功；未完成动作失败，重连后不自动续跑。
- 离线拒绝结果与现有去重缓存一样，在进程内保留最近 1024 条；同消息 ID 的
  重投不会在恢复后补执行。这不是跨进程、永久的去重保障。
- 绝对运动完成必须满足目标轴使能、无相关故障、停止且规划位置达标；开启真实
  编码器反馈时还校验实际位置。未接入真实反馈时，仍不能证明机械结构实际到位。
- 断电后的坐标参考不能仅凭使能恢复判为有效；必要时由操作员在安全条件下回零。

## SDK 卡死边界

若原生 DLL 调用长时间不返回，看门狗仍会上报离线并阻止新指令。清理和重连
必须等旧调用退出，不能在旧线程使用对象时销毁 DLL 对象。永久卡死需要重启
Adapter 进程；正常停机也可能等待该调用。软件看门狗不是设备侧急停，网络断开
时不能保证停止命令到达硬件。

## 验证与应用

离线回归命令：

```powershell
D:/Python/python.exe -m unittest discover -s adapter/new/MotionStageController/tests -v
```

覆盖断线、冻结/倒退的时钟、阻塞 SDK、失能轴、迟到结果、重连不续跑、
离线命令去重、及时心跳和启动不阻塞等情况。加载 DLL 的测试只构造/销毁对象，
不打开运动卡。部署时需更新运行电脑上的文件并在设备空闲时重启 Adapter；
当前开发验证没有启动现场控制、改变设备状态或重启任何服务。
