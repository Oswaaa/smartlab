MOTIVATION 范式演进
2 背景问题：从驱动单机到完成任务
化学实验自动化正经历从底层指令调度到任务级系统级组织的深刻变革
关键洞察： 核心矛盾不再是“会不会给某台设备发指令”，而是“在实验全过程中，执行是否沿着一条语义明确、状态闭环、边界受控的链路被组织”。
任务执行必须同时回答的四大关键要素
1. 资源如何组织 (Resources)

设备能力如何抽象？设备与步骤如何建立动态绑定与独占关系？

2. 状态如何演化 (States)

物理硬件的运行态、指令生命周期与业务异常如何同步追踪？

3. 数据如何传递 (Data Propagation)

实验参数、实时传感器数据、物料上下文在步骤间如何安全流动？

4. 边界如何监督 (Constraints & Safety)

危险温度、超压、溢流等异常工况如何在毫秒级被检测与联锁处置？

实验室自动化范式升维
旧范式：单点设备驱动 (Device-Centric)

只要把串口/网口调通，向 PLC 下发十六进制指令即算完成。状态判断与错误重试分散在业务代码各处，流程黑盒化。

新要求：任务导向可执行闭环 (Task-Oriented)

以科学实验任务为中心，将异构设备抽象为规范化可执行切片，全生命周期由严密状态机接管，确保可观测、可审计、可联锁。

RELATED WORK 现有工作对比
3 现有工作分析与研究空白
脚本接口、工作流编排与数字孪生各自的优势及其共同缺口
核心缺口： 调用、编排与建模仍常被分开处理；缺少把能力、运行状态、数据依赖与执行约束接到同一条任务执行链路上的方法。
1. 脚本与设备接口
如 Python 脚本、SiLA 2、厂商 SDK
  • 优势: 擅长物理通信与灵活发令
  • 隐患: 状态与约束散落在代码中
  • 缺陷: 缺乏全局统一的模型约束与数据流规约
2. 工作流编排
如 BPMN、Node-RED、科学工作流
  • 优势: 擅长步骤排序与依赖拓扑
  • 隐患: 节点多被当作简单“黑盒动作”
  • 缺陷: 编排后发令常另走通道，不管物理状态
3. 模型与数字孪生
如 MBSE、SysML、三维孪生
  • 优势: 擅长宏观资产与能力结构描述
  • 隐患: 常停在静态“说明书/大屏看护”
  • 缺陷: 缺少接入同一次任务控制路径的方法
技术流派 设备接入与下发 任务步骤编排 设备状态机闭环 数据流与控制流分离 任务级安全联锁约束

RESEARCH QUESTION 核心立论
4 核心科学与工程问题收束
用形式化、不可妥协的硬性约束界定系统设计目标
Core Problem Statement
如何构造一条任务执行链路，
使工作流节点、设备状态机、适配器与物理设备处在同一条控制路径上，
并让状态、数据与约束也在这条链路中被统筹观察与联锁监督？
核心公理与硬性要求：任务工作流绝对不得旁路设备状态机！
CORE METHOD 主张与概念切片
5 核心主张：执行链路与任务切片
非旁路单步纵向链路与多步横向编排的正交融合
核心主张： 不是提供孤立物模型或独立流程图，而是确立不可旁路的单步纵向链路，并将任务工作流定义为横向时序上的可执行切片。
纵向概念结构图 (单步执行闭环)
纵向铁律：信号去程必由状态机命令驱动，反馈回程原路收敛
横向概念结构图 (多步时序编排)
执行切片 (Execution Slice) = 横向编排 $\times$ 纵向链路
为什么称为“切片”？
针对具体实验任务，工作流从全实验室庞大拓扑中动态切出一组有序执行序列；每一序列节点向下投影为具体的纵向设备状态机路径，实现两维正交自洽。
旁路状态机的危险：
若工作流直接命令设备驱动，流程便不知道设备真实物理状态，状态机退化为被动看护者，整个系统的形式化保障随之崩溃。
ARCHITECTURAL CONTRAST 路径级对照
6 对照：发令究竟走哪条路？
深入对比“常见旁路模式”与“本文不可旁路闭环模式”的本质差异
判定标准： 衡量物模型真伪的关键，在于模型是否处在发令与异常收敛的必经之路上，而非仅充当静态看护看板。
常见对照形态 (旁路发令 / 模型边缘化)
  • 流程图扮演总控，物模型主要用于被动可视化；
  • 流程可绕过状态机，直接跨层向底层驱动发令；
  • 危害：指令执行失控、状态死锁、安全约束无法拦截。
本文规范要求 (状态机闭环 / 不可旁路)
  • 流程节点只能向设备状态机发送标准化执行信号；
  • 状态机根据当前合法状态与内禀约束决定是否命令适配器；
  • 收益：设备模型真正进入控制闭环，异常自动收敛。
FORMAL SPECIFICATION 系统形式化四元组
7 核心方法形式化：$\mathcal{L} = \langle \mathcal{R}, \mathcal{F}, \mathcal{C}, \Pi \rangle$
为实验任务可执行建模提供完备、严密的数学与工程抽象
体系总览： $\mathcal{L} = \langle \mathcal{R}, \mathcal{F}, \mathcal{C}, \Pi \rangle$ 确立了四维正交分工，实现了从静态设备、动态流程到安全监督的形式化推导。
$\mathcal{R}$
资源层 (Resources)

回答设备如何成为链路上的可执行对象

  • 能力模型：属性/参数/契约
  • 双空间状态机：CMD + OP
  • 内禀硬约束监测与物理锁存
$\mathcal{F}$
工作流层 (Workflow)

回答一次任务如何横向组织步骤并接入链路

  • DEV / FUNC / SUBFLOW 节点
  • 接口传信号，端口拉数据
  • 100ms 冻结快照与上升沿触发器
$\mathcal{C}$
约束层 (Constraints)

回答安全边界如何在链路上被实时监督

  • 三层防护：内禀 / 基线 / 任务
  • 6类可观测对象权威快照
  • 时序窗口函数 (delta/avg/rate)
$\Pi$
协议层 (Protocols)

回答跨层信号与报文如何统一定义

  • 统一数据类型 DataType
  • 跨层控制信号 (WF / CMD / OP)
  • MQTT 5 类标准通信报文契约
LAYER R 资源层建模
8 资源层 $\mathcal{R}$：设备对象模型
能力模型（静态语义）与双空间状态机（动态控制）双轮驱动
核心机制： 能力模型提供语义，状态机履行控制。状态机必须留在发令路径上，否则能力模型只是说明书。
设备对象模型结构 (Device Object Model)
双状态空间与指令独占
  • CMD 空间: 对普通指令严格单指令独占，防止并发冲突；
  • 附属终止: 普通指令被中断时，动态创建附属终止状态机下发中止，带全局唯一 messageId；
  • 可插队急停: 急停指令不受空闲限制，立即插队抢占下发。
内禀约束物理锁存 (Latch)
  • 由 IntrinsicConstraintMonitor 独立周期轮询设备最新属性；
  • 违规时将异常状态幂等加入 EXCEPTION 集合；
  • 硬锁存机制: 物理条件恢复后绝不自动移出，必须经人工复核解除，杜绝物理间歇抖动隐患。
LAYER F 工作流层与机制
9 工作流层 $\mathcal{F}$ 与节点触发器机制
接口/端口正交分离通道体系与 100ms 上升沿触发求值
通道分离原则： 接口传控制信号（活边实时转发），端口传工艺数据（下游主动只读拉取），源步骤终态绝对冻结。
控制信号流与数据流正交分离通道体系
  • 接口活边转发 (Interface): 仅传递控制状态 (ACTIVE, START, ABORT)，不存队列，直投快照；
  • 下游按需拉取 (Port): 目标活跃时才主动拉取数据，严禁逆向篡改上游数据，确保数据不可逆溯源。
100ms 冻结快照与上升沿触发器
100ms 冻结快照 (Frozen Snapshot)

每轮轮询开始时，瞬间冻结全图接口与变量快照。当轮计算新产生的值在下一轮生效，保障大规模并发拓扑求值的数学确定性。

上升沿条件触发 (Rising-Edge Triggers)

bindingTriggers 仅当条件从 false 跃变为 true 的瞬间触发一次内联动作 (UPDATE / EMIT)，杜绝高电平持续误触发。

复杂逻辑增强与主张界限

触发器赋予了工作流原生的条件分支、等待与循环能力；但牢记：触发器是能力补充，绝不以触发器削弱或代替“不可旁路状态机”的主张。

LAYER C 安全联锁
10 约束层 $\mathcal{C}$：三层立体防御体系
内禀约束、实验室基线与任务约束构建的软实时联锁网络
设计精髓： 约束引擎为纯逻辑旁路计算，不直接侵入执行主循环；基于权威内存快照与时序窗口防抖，实施分级处置。
约束三层立体防御架构 (Three-Tier Constraint Structure)
双轨软实时调度
  • 事件驱动: 可观测量变更即刻抛出内部事件，异步唤醒求值；
  • 200ms 定时驱动: 周期时钟兜底扫描，为滑动窗口函数兜底；
  • 权威内存快照: 纳秒级直接读取，绝不碰数据库。
时序滑动窗口与防抖
  • delta(var, s): 过去 $N$ 秒内物理量变量变化值；
  • avg(var, s): 过去 $N$ 秒内的移动平均平滑值；
  • rate(var): 物理量升降变化速率；
  • windowSeconds 防抖: 异常持续超过阈值才触发，过滤瞬态毛刺。
CASE STUDY SmartLab 2.0 原型验证
11 实现案例：反应釜控温全链路验证
验证框架的可实例化、语义可检查性与工程闭环（SmartLab 2.0 原型）
案例定位： 证明整条不可旁路链路完全能够实例化且软硬件闭环执行，语义留在模型中，适配器纯做协议转换。
反应釜加热端到端执行信号流序图
原型系统 SmartLab 2.0
  • 后端平台: Spring Boot 3 + Java 21 现代技术栈；
  • 协议中间件: EMQX MQTT Broker (QoS 1 保证)；
  • 边缘端驱动: Python / C++ 标准四层 Adapter 架构；
  • 前端可视化: Vue 3 + Vue Flow 动态执行流甘特图。
案例验证的核心结论
  • 语义留在模型中: 业务逻辑完全由状态机与工作流表达；
  • 适配器不越权: 边缘驱动仅负责 Modbus 与 MQTT 协议翻译，严禁包含业务总控；
  • 异常收敛性: 无论是温度越界还是网络断连，状态机均能严密收敛至终态。
SUMMARY 学术贡献与展望

三大主要贡献 (Contributions)
  • 1. 确立不可旁路的执行链路:
    改变传统“工作流直连设备”或“物模型仅充当看护”的割裂做法，确立了状态机在发令必经之路上的核心地位。
  • 2. 形式化四元组与触发器:
    构建了 $\mathcal{L} = \langle \mathcal{R}, \mathcal{F}, \mathcal{C}, \Pi \rangle$ 完备体系，以接口/端口分离和上升沿触发器突破了传统工作流条件循环表达弱的瓶颈。
  • 3. 原型落地与可检查性:
    开发 SmartLab 2.0 原型系统，打通真实硬件协议闭环，证明了该理论方法的可工程化落地。
客观研究边界 (Limitations)
定位是可执行性示意，非极限 Benchmark
  • 规模限制: 当前案例聚焦典型反应单元，尚非数百台设备的超大规模集群；
  • 并发调度: 重点在于单任务链路的闭环与收敛，多任务多资源争用调度算法正在扩展；
  • 长时程验证: 尚需经过数月连续不间断化工合成实验的耐久性检验。
未来演进展望 (Future Work)
  • 数字仿真与虚拟执行:
    在物理实验下发前，基于虚拟孪生与动力学模型在数字空间全速预演，排查死锁与冲突。
  • 量化工程指标评估:
    系统统计并量化分析模型复用率、实验覆盖率、变更影响分析等软件工程指标。
  • 科学闭环智能体演进:
    从当前的大模型生成流程草稿，进阶到基于分析仪器图谱自动反思迭代的自闭环科学家 Agent。

DEFENSIVE Q&A 答辩应对锦囊
14 Q&A 专家高频提问与防御性备用短答
针对国际审稿人与现场评委最可能发起的四大质疑准备的标准应答口径
Q1: 你们和市场上现有的“物模型 + 流程图”有何本质区别？
核心答复口径：
“区别不在于有没有物模型和流程图，而在于发令是否必须经过状态机。市场上常见形态是流程图总控，物模型主要用于被动看护，流程可以直接旁路发令到设备；而我们强制规定流程节点只能向状态机发信号，状态机留在发令必经之路上，使设备模型真正进入了控制闭环。”
Q2: 别人系统里的设备驱动或网关里早就有状态机了，你们新在哪里？
核心答复口径：
“我们不声称自己是第一次把状态机放到控制路径上。我们声称的贡献是：在任务执行切片这一顶层视角下，明确了任务工作流与设备状态机之间不可旁路的对应关系，并将数据端口、接口信号和多层约束统一接驳在这条链路上，消除了传统多层软件各自为政的割裂。”
Q3: 你们的框架是否依赖当下火热的大模型（LLM）来生成工作流？
核心答复口径：
“大模型绝非本文的核心立论。 本文聚焦于可执行建模与闭环执行链路本身。无论流程是由实验员人工拖拽、化学脚本导出、还是由大模型自然语言生成，最终产物都必须符合我们的 JSON Schema，并且都必须遵从本框架不可旁路状态机的安全铁律。”
Q4: 论文中为何没有展示大规模吞吐量或并发性能的定量对比 Benchmark？
核心答复口径：
“本文当前定位是系统级可执行性示意与语义正确性闭环验证，而非针对服务器吞吐量的 Benchmark。我们首要解决的是化学实验‘能否安全闭环、状态是否自洽’。正如展望中所述，未来我们将在更复杂的工业反应场景中开展大规模长时程量化评估。”
