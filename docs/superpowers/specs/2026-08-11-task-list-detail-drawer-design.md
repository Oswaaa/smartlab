# 任务列表详情抽屉设计

## 目标

任务列表页面保持完整、连续的列表工作区，不在页面中常驻详情区域。用户通过每行的“详情”操作打开右侧抽屉，在不离开任务列表上下文的情况下查看运行监控、流程图、步骤、设备绑定、任务约束和业务事件。

## 交互规则

- 任务列表首屏只展示页面标题、状态摘要、筛选区、任务表格和分页。
- 只有明确点击“详情”按钮才打开任务详情；点击普通表格行不打开抽屉，避免浏览和选中文本时误触。
- 详情抽屉从右侧打开，桌面端宽度为视口的 78%，窄屏降级为全宽。
- 抽屉打开后保留列表作为遮罩后的背景上下文，关闭后回到原列表位置和筛选状态。
- 抽屉头部只保留一层任务身份信息，包含任务名称、编号、流程名称、状态、刷新与终止操作。
- 抽屉页签固定为：运行概览、执行流程图、步骤详情、设备绑定、任务约束、业务事件。
- 默认进入“执行流程图”，优先选中当前运行步骤；没有运行步骤时选中最新可用步骤。
- 运行中任务继续按既有机制刷新运行数据；关闭抽屉时停止详情轮询。

## 视觉结构

### 任务列表

- 使用安静、紧凑的运维控制台风格。
- 状态摘要作为可点击筛选条，与列表卡片形成一个整体。
- 表格重点展示任务、流程、状态、当前节点、执行周期、设备与约束、操作。
- “详情”为主要查看操作；启动、终止、删除根据任务状态按原有业务规则显示。

### 详情抽屉

- 抽屉头部、页签栏和内容区分层明确，不重复显示 Element Plus 默认标题和自定义标题。
- 执行流程图采用“流程画布 + 当前步骤详情”的双栏结构。
- 运行概览保持指标摘要和任务基础信息；其他页签继续复用现有业务组件与数据接口。
- 业务事件只展示面向业务与执行结果的事件，不展示工作流引擎轮询细节。

## 数据与接口边界

- 不修改后端接口、任务状态模型或轮询协议。
- 复用现有任务列表、步骤快照、运行日志、流程定义、资源绑定与有效约束接口。
- 前端只新增纯展示推导逻辑，用于状态文案、抽屉标题和默认步骤选择。

## 验收标准

- 任务列表不再通过整行点击打开详情。
- 点击任意任务的“详情”按钮打开 78% 右侧抽屉。
- 抽屉默认展示执行流程图，并优先选中 RUNNING 步骤。
- 六个详情页签、刷新和终止操作保持可用。
- 页面在桌面与窄屏下无明显横向溢出，前端构建通过。
