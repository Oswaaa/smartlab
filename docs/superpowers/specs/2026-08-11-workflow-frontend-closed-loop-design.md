# SmartLab 工作流前端闭环设计

日期：2026-08-11  
状态：已确认，待实施计划

## 1. 背景

工作流后端已经具备节点级轮询、内联 `EMIT` / `UPDATE` 动作、触发器上升沿、生命周期转移校验、规范化接口快照、同任务子流程和任务级并发调度能力。前端下一阶段不再扩展执行协议，而是把现有能力组织成完整、可理解、可操作的业务闭环。

当前前端已经有两个独立菜单页面：

- 流程设计：工作流建模、节点配置、连线、校验、保存草稿和发布启用。
- 任务列表：任务创建、资源绑定、任务约束、启动、终止和运行查看。

触发器配置和运行监控都不是新的页面：触发器配置属于流程设计器的节点配置区；运行监控属于任务列表的任务详情抽屉。

## 2. 设计目标

1. 建立“流程设计 → 发布 → 创建任务 → 资源绑定与约束 → 执行 → 监控”的完整业务闭环。
2. 让节点在画布上直接表现控制接口和数据端口，降低连线歧义。
3. 让节点配置结构与工作流模型保持一致，不再把触发器拆成独立页面。
4. 区分系统契约和用户配置，防止系统默认接口、端口和触发器被误改。
5. 在任务详情中同时提供图形化执行拓扑和结构化步骤详情。
6. 运行事件只呈现业务事实，不暴露工作流引擎轮询、线程或调度器实现细节。
7. 将超大页面拆分为页面域内聚组件，提高可维护性和可测试性。

## 3. 设计原则

### 3.1 业务结构优先

先按业务职责划分页面和交互状态，再借鉴成熟云控制台的工作台、主从视图、详情抽屉、密集表格和就地校验模式。不机械复制某一家产品的界面。

### 3.2 页面数量保持不变

顶部主菜单保留两个独立菜单项：`任务列表` 和 `流程设计`。页面内部不得再增加模拟这两个页面的二级切换栏。

### 3.3 系统契约只读

后端模板或规范化过程注入的系统接口、端口、动作能力和触发器必须带有稳定的系统标识。前端以锁定状态展示，禁止重命名、删除或更改其结构与动作内容。

### 3.4 业务事件与技术诊断分离

用户界面只显示任务、节点、信号、设备调用、子流程和异常相关的业务事件。轮询次数、扫描周期、线程分配、队列领取和调度器心跳不属于任务业务事件。

## 4. 信息架构与业务流程

### 4.1 流程设计闭环

1. 用户从设备库或流程库选择资源。
2. 用户将设备能力节点、子流程节点或功能节点加入画布。
3. 用户通过画布上的控制接口建立执行流，通过数据端口建立数据流。
4. 用户在右侧节点配置区完成业务配置、变量空间、数据端口、控制接口和生命周期配置。
5. 用户运行静态校验并处理错误或提醒。
6. 用户保存草稿，确认后执行“发布启用”。

### 4.2 任务创建闭环

1. 用户在任务列表中选择“新建任务”。
2. 用户选择已发布并可执行的流程模型。
3. 前端运行任务预检并展示阻断项与提醒。
4. 用户按节点出现路径绑定具体设备实例。
5. 用户配置可选的任务级约束。
6. 用户确认并创建任务。

### 4.3 任务执行与监控闭环

1. 用户从任务列表启动处于 `PENDING` 的任务。
2. 用户打开任务详情抽屉查看运行概览或执行流程图。
3. 用户点击运行图中的节点，查看对应 `TASK_STEP` 的接口快照、变量空间和日志。
4. 用户可切换查看设备绑定、任务约束和业务事件。
5. 任务运行期间前端自动刷新；终态任务停止自动刷新并保留最终视图。

## 5. 流程设计页面

### 5.1 页面布局

采用稳定三栏工作台：

- 左栏：设备库和流程库，提供搜索、树形分组、拖拽与双击添加。
- 中栏：Vue Flow 画布、流程工具栏、功能节点工具条、画布控制和连线图例。
- 右栏：当前流程总览、校验结果、连线详情或节点配置。

工具栏保留“新建、导出、校验、保存草稿、发布启用”。“发布启用”文案不修改。

### 5.2 节点画布表现

节点卡片必须直接表现它声明的接口和端口：

- 控制接口使用圆形连接点和蓝色语义。
- 数据端口使用菱形或方形连接点和紫色语义。
- `IN` 位于节点左侧，`OUT` 位于节点右侧。
- 连接点附近显示短名称；过长名称省略并通过悬浮提示显示全名。
- 控制流使用蓝色实线；数据流使用紫色虚线。
- 节点选中、警告、错误和运行时状态不能只依赖颜色，必须同时使用图标、文本或边框状态。

节点本体只展示识别所需信息：节点类型、名称、设备能力或表达式摘要。接口和端口是节点的一部分，不放到独立浮动面板中。

### 5.3 节点配置标签

右侧节点配置区固定使用以下五个标签：

1. 业务配置
2. 变量空间
3. 数据端口
4. 控制接口
5. 生命周期

标签顺序保持稳定。某类节点不适用某项配置时，标签保持可识别但显示只读说明或空状态，不改变其他标签位置。

#### 业务配置

- `DEV_NODE`：设备模型、能力选择和能力参数。
- `SUBFLOW_NODE`：引用流程模型及其进入、完成语义。
- `BRANCH` / `AGGREGATE`：计算表达式。
- `START` / `END`：节点业务语义和系统行为说明。

切换设备能力时不保留旧能力参数，即使参数名称和类型相同也重新按目标能力初始化。

#### 变量空间

- 展示并编辑节点 `internalVariables`。
- `DEV_NODE.attributesMapping` 只允许绑定设备模型已声明的属性。
- `_triggerStates` 是运行时系统保留键，不在设计态变量空间中出现。

#### 数据端口

- 编辑端口名称、方向和绑定内部变量。
- 系统默认端口只读。
- 删除自定义端口前展示受影响的数据连线并要求确认。

#### 控制接口

- 按 `OUT → IN` 顺序展示接口。
- 每个接口显示方向、接口类型、允许信号和触发器数量。
- 使用“接口列表 + 当前接口详情”的主从结构，避免同时展开所有触发器表单。
- 当前接口详情内集中编辑允许信号和 `bindingTriggers`。

#### 生命周期

- 展示初始状态、状态集合和合法转移。
- 运行时生命周期仍存储在 `TASK_STEP.NODE_STATUS`，不属于变量空间。
- 功能节点没有生命周期时显示明确的“不适用”说明。

### 5.4 接口与触发器权限

#### 系统默认项

所有节点类型的系统默认接口、端口和触发器均只读：

- 显示锁定标识和“系统默认”说明。
- 禁止重命名、删除、改变方向、接口类型、允许信号、条件和动作。
- 只读规则同时由前端交互、保存前校验和后端编译校验保证。

#### 功能节点

`FUNC_NODE` 是唯一允许新增用户自定义控制接口和用户触发器的节点类型：

- 可以新增、编辑和删除用户自定义接口。
- 可以在用户自定义接口上新增、编辑和删除触发器。
- 系统默认接口和系统默认触发器仍保持只读。
- 分支和聚合通过自定义输出接口支持 N 路控制流。

#### 设备能力节点

`DEV_NODE` 的控制契约来自设备能力模板和工作流规范：

- 不提供新增或删除控制接口的入口。
- 不允许修改系统触发器。
- 用户只在“业务配置”中选择能力并填写能力参数，在“变量空间”中配置属性映射。
- 控制接口标签仍可查看接口、允许信号、默认触发器和动作，便于理解执行行为。

#### 子流程节点

`SUBFLOW_NODE` 的开始和完成调度由工作流引擎负责：

- 不允许新增、删除或修改系统控制接口和触发器。
- 控制接口标签只读展示父流程激活和 `SUBFLOW_COMPLETED` 完成语义。

### 5.5 触发器编辑

触发器仍内联在接口配置中，不新增页面或独立路由。

条件编辑器包括：

- `object`：内部变量、`nodeLifecycleState`、当前宿主接口的 `signalName` / `payload` 路径，以及仅对 `BRANCH` / `AGGREGATE` 可用的表达式计算结果。
- `operator`：系统执行规范声明的约束操作符。
- `threshold`：按已知目标类型提供布尔、数字、字符串、枚举或 JSON 输入。

条件对象不得直接引用设备遥测字段。设备遥测通过 `attributesMapping` 同步到节点内部变量后再由触发器引用。

动作编辑器包括：

- `EMIT`：目标只能是本节点 `OUT` 接口；信号必须来自该接口 `allowedSignals`。
- `UPDATE / NODE_LIFECYCLE`：目标状态必须属于节点生命周期；运行时仍由后端依据当前状态和 `transitions` 校验。
- `UPDATE / INTERNAL_VARIABLE`：选择目标变量后，在“直接常量”和“计算表达式”之间二选一；`value` 与 `valueExpression` 不得同时存在。

界面必须明确提示：每个触发器独立求值，同一轮询内多个触发器同时满足时都可执行；持续为真的触发器依靠上升沿状态避免重复动作。

## 6. 任务列表页面

### 6.1 页面主视图

保留当前任务列表能力：

- 状态汇总条。
- 任务名称或说明搜索。
- 状态筛选、查询和重置。
- 任务表格和分页。
- 启动、终止、查看详情等行级操作。
- 新建任务入口。

任务表格继续显示资源绑定数量和任务约束数量，让用户不进入详情也能判断任务配置完整性。

### 6.2 新建任务抽屉

保留并优化现有功能，不改变业务能力：

- 基本信息与流程选择。
- 任务预检。
- 按设备节点路径进行资源绑定。
- 任务级约束查看、新增、编辑和删除。
- 创建前汇总阻断项与提醒。

资源绑定和任务约束不迁移到新的独立页面。

### 6.3 任务详情抽屉

任务详情继续使用约 78% 宽度的右侧抽屉，包含：

1. 运行概览
2. 执行流程图
3. 步骤详情
4. 设备绑定
5. 任务约束
6. 业务事件

抽屉标题区显示任务名称、任务 ID、状态、最近刷新时间以及当前合法操作。

### 6.4 执行流程图

增加图形化运行视图，并与步骤树互补而不是互相替代：

- 使用已发布流程的定义拓扑作为底图。
- 按 `TASK_STEP.NODE_STATUS` 为节点叠加等待、运行、成功、失败、终止状态。
- 子流程步骤仍属于同一个 `TASK_ID`，按 `parentStepId` 和 `stepDepth` 在父节点内部或可展开分组中展示。
- 选择图中节点后，在右侧显示对应步骤的概览、接口快照、变量空间和日志。
- 未创建步骤的下游节点显示等待状态，不伪造 `TASK_STEP` 数据。
- 同一任务内节点按引擎顺序求值；设备和子流程的外部执行可以并行。运行图只表现业务状态，不暗示每个节点拥有独立线程。

### 6.5 步骤详情与接口快照

- 步骤层级由 `parentStepId` 和 `stepDepth` 构建。
- 接口快照按规范化 JSON 数组展示，保持接口声明顺序。
- 每行显示方向、接口名称、当前 `signalName` 和 `payload`。
- 尚未收到或发送信号的接口仍保留，显示 `signalName: null` 的用户语义。
- 不显示 `sourceNodeIdRef`、路由信封或旧的 `inputSignalName` 等非规范字段。
- 变量空间默认隐藏 `_triggerStates`，其余变量使用结构化键值或 JSON 预览。

### 6.6 业务事件

业务事件只包含用户可理解、可追踪的执行事实：

- 任务创建、启动、成功、失败和终止。
- 节点生命周期迁移。
- 接口信号接收与发送。
- 设备控制信号发送、设备状态或结果返回。
- 子流程启动与 `SUBFLOW_COMPLETED`。
- 约束违规及处置动作。
- 业务异常和失败原因。

以下内容不得进入任务业务事件：

- 工作流轮询次数和轮询完成记录。
- 线程池领取、释放或排队过程。
- 调度器扫描、锁续期或心跳。
- 纯技术缓存和内部重试细节。

如未来需要引擎诊断，必须放入仅管理员可见的独立技术诊断面板，不能混入任务执行事件。

### 6.7 刷新策略

- 后端任务引擎仍使用默认 100ms 可配置轮询。
- 前端运行抽屉默认每 1 秒刷新一次，只刷新当前打开任务。
- 任务进入终态后停止自动刷新。
- 页面显示“最近刷新时间”和手动刷新操作。
- 前端刷新周期不冒充引擎执行精度。

## 8. 视觉与交互规范

- 延续现有工业浅色控制台和 Element Plus，不新增 UI 依赖。
- 使用白色工作区、浅灰背景、1px 边界和 4–6px 圆角；阴影只用于浮动工具条和抽屉层级。
- 主色仅用于主要操作、选中态和控制接口；紫色用于数据端口和数据连线。
- 状态色保持语义稳定：运行蓝、成功绿、提醒橙、失败红、等待灰。
- 页面使用紧凑的 12–14px 正文和清晰字段标签，不使用装饰性渐变、大标题或嵌套卡片。
- 陌生图标必须有文字或悬浮说明；键盘焦点和禁用状态必须可见。
- 设计器以桌面端为主。小于 1280px 时压缩资源栏和检查器；更窄尺寸将检查器切换为抽屉，不缩小文字到不可读尺寸。

## 9. 错误处理与校验

- 节点标签显示对应错误计数，点击校验问题定位到具体节点、接口、端口或触发器。
- 保存前校验系统项未被修改、自定义接口引用有效、动作能力存在、`EMIT` 信号合法、`UPDATE` 目标合法、`value` 与 `valueExpression` 互斥。
- 接口快照不是规范数组时，不转换旧路由信封；界面显示“快照格式不符合当前协议”的明确错误。
- 运行图缺少节点定义或步骤关联时显示局部未知状态，不阻塞其他合法步骤的展示。
- 网络刷新失败时保留最后一次成功数据，显示失联提示和手动重试，不清空运行视图。

## 10. 测试策略

实施采用 TDD，至少覆盖：

### 流程设计

- 节点画布渲染控制接口和数据端口，并按方向放置。
- 系统接口、端口和触发器不可编辑或删除。
- `FUNC_NODE` 可以新增自定义接口和触发器。
- `DEV_NODE` 和 `SUBFLOW_NODE` 不显示新增控制接口入口。
- 控制接口按 `OUT → IN` 排序。
- 条件对象不再出现 `inputSignalName` 等旧别名。
- `EMIT` 只允许目标 OUT 接口及其允许信号。
- `UPDATE` 常量与表达式互斥。
- 切换设备能力后不保留旧能力参数。

### 任务列表与运行监控

- 新建任务继续包含预检、资源绑定和任务约束。
- 运行图按步骤状态渲染，未创建步骤显示等待。
- 子流程按 `parentStepId` / `stepDepth` 建立层级。
- 选择运行图节点后展示正确 `TASK_STEP` 详情。
- 规范化接口快照数组、空信号和 JSON 载荷正确显示。
- `_triggerStates` 不出现在普通变量空间中。
- 设备绑定和任务约束在详情抽屉中可查看。
- 业务事件中不出现轮询、线程或调度器内部记录。
- 运行任务自动刷新，终态任务停止自动刷新。

### 回归验证

- 更新移动后的组件路径测试。
- 运行前端全部测试。
- 运行 Vite 生产构建。
- 对 1440px、1280px 和 1024px 关键状态进行浏览器视觉检查。

## 11. 验收标准

1. 顶部菜单中的任务列表和流程设计仍是两个独立路由页面。
2. 流程设计器节点可直接辨认控制接口、数据端口及其方向。
3. 节点配置严格使用五个确认标签，触发器位于控制接口内部。
4. 系统默认接口、端口和触发器无法被前端修改。
5. 只有功能节点能新增用户控制接口和触发器。
6. 设备能力节点与子流程节点的系统控制契约只读。
7. 任务创建的资源绑定、预检和任务约束能力全部保留。
8. 任务详情同时支持执行流程图和结构化步骤详情。
9. 运行图能正确表达子流程层级和节点执行状态。
10. 业务事件不暴露轮询、线程和调度器内部实现。
11. 接口快照和状态名称与当前后端规范一致。
12. 前端全部测试和生产构建通过；既有 WebSocket 端口噪声不作为功能失败，但需要在验证记录中如实说明。

## 12. 非目标

- 不修改工作流引擎轮询、并发和子流程调度算法。
- 不新增数据库字段或改变 `TASK_STEP` 表结构。
- 不重新设计设备模型、设备实例、数据中心或约束管理页面。
- 不新增前端框架、状态管理库或可视化依赖。
- 不在任务业务事件中增加引擎技术诊断数据。
