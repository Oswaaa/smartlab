# 流程设计器编排体验与触发器配置改造规格

日期：2026-08-12  
状态：已实施并通过验证

## 1. 目标

本轮改造聚焦流程设计页面的实际编排体验，在不改变既有工作流运行模型的前提下，完成以下目标：

1. 恢复画布工具栏中的功能节点入口，左侧资源栏只承担设备资源与流程资源浏览。
2. 统一设备库、流程库的树形导航样式，使信息层级清晰、操作状态可辨识。
3. 为已保存流程增加“查看 / 编辑”模式，避免仅查看流程时产生误改。
4. 简化设备能力节点、控制接口和触发器配置，确保界面字段直接对应模型与协议规范。
5. 为功能节点提供受约束的计算表达式编辑体验，降低拼写错误和无效表达式进入后端的概率。
6. 补足后端规范化与编译校验，保证前端便利操作不会破坏执行语义。

## 2. 不在本轮范围内

- 不修改数据库表结构。
- 不改变工作流引擎“任务级并行、任务内节点按顺序轮询”的执行模型。
- 不改变触发器的上升沿、防重复触发和 `_triggerStates` 持久化机制。
- 不引入符号数学求导；只提供实验室节点内部变量常用的少量时序函数。
- 不允许功能节点直接读取设备遥测；设备遥测仍通过属性映射同步为节点内部变量。
- 不重做工作流 JSON Schema；同级对象关系等 Draft-07 无法表达的规则继续由后端校验。

## 3. 页面整体结构

### 3.1 左侧资源栏

左侧保留两个切换项：设备库、流程库。视觉结构复用设备模型页面侧边栏的成熟样式：紧凑行高、文件夹/文件图标、悬停反馈、当前项浅蓝背景和左侧强调线，不使用大卡片或多余留白。

#### 设备库

层级固定为：

```text
设备类别
└─ 设备模型
   └─ 设备实例
      └─ 设备能力
```

- 类别和模型使用文件夹图标。
- 实例和能力使用对应的轻量图标。
- 搜索同时匹配类别、模型、实例与能力名称，并保留匹配项的上级路径。
- 只有设备能力可拖入或双击加入画布。
- 查看模式下仍可浏览资源，但禁止拖入和双击添加。

#### 流程库

流程当前没有独立的业务分类字段，因此只在界面上按状态分组，不伪造持久化分类：

```text
已启用流程
└─ 流程模型
草稿流程
└─ 流程模型
```

- 状态分组使用文件夹图标，流程使用文件图标。
- 点击流程后加载到画布，并默认进入查看模式。
- 当前加载流程在树中保持选中态。
- 搜索匹配流程名称与描述。

### 3.2 功能节点工具栏

功能节点恢复到画布上方原有工具栏，不再占用左侧资源树：

- 开始节点
- 结束节点
- 条件分支
- 聚合节点

编辑模式下可点击添加或拖入画布；查看模式下整体禁用，并通过统一的禁用样式表达状态。

### 3.3 画布命令栏

命令栏至少包含：新建、编辑、清空、静态检查、保存草稿、发布启用。

- 新建：创建空白流程并直接进入编辑模式。
- 编辑：仅在已加载流程的查看模式显示为主要操作；点击后进入编辑模式。
- 清空：仅编辑模式可用。二次确认后，只清空节点及节点间连接，保留流程名称和描述；保存之前不写数据库。
- 静态检查：查看与编辑模式都可用。
- 保存草稿、发布启用：仅编辑模式可用。
- 加载另一条流程、刷新页面或离开页面时，如存在未保存修改，继续使用现有的离开确认机制。

### 3.4 查看模式边界

查看模式允许：

- 缩放、平移和适配画布。
- 点击节点打开详情抽屉。
- 查看节点全部配置和系统触发器说明。
- 执行静态检查。

查看模式禁止：

- 新增、删除、移动节点。
- 新增、删除或重连连线。
- 修改流程名称、描述和节点配置。
- 从资源库或功能节点工具栏添加节点。

进入编辑模式后才开放上述变更。节点详情抽屉在查看模式下以只读内容呈现，不使用大量灰色禁用输入框。

## 4. 节点抽屉与业务配置

### 4.1 抽屉结构

抽屉继续采用紧凑的上下结构：节点信息头部与配置详情区域无异色断层和多余外边距。抽屉宽度以当前较宽版本为基础适度收窄，但保证触发器编辑区域不挤压；建议桌面端宽度约为视口的 46%，并设置 720px 至 900px 的边界。

顶部固定显示：节点名称、节点类型、内部变量数量、数据端口数量、控制接口数量，并放置删除节点操作。删除只在编辑模式可见。

### 4.2 设备能力节点业务配置

“设备能力”和“能力参数”合并为一个连续区域，不再拆成两个卡片：

```text
业务配置
  设备能力  [能力下拉框]
  参数配置
    参数名称 / 类型标签 / 紧凑值输入
```

- 切换能力时按既定规则清空原能力参数，不保留同类型参数值。
- 无参数时显示一行轻量说明，不使用插画式空状态。
- 参数输入根据数据类型选择数字、文本、布尔或枚举控件，限制最大宽度，避免横向铺满抽屉。

## 5. 控制接口配置

### 5.1 字段显示

与模型和协议中的固定枚举保持一致，不翻译以下运行时标识：

- 接口方向：`IN`、`OUT`
- 接口类型：`WORKFLOW`、`STATE`
- 动作类型：`EMIT`、`UPDATE`

字段标题与帮助信息仍使用中文。

### 5.2 系统接口与自定义接口

- 系统接口、系统触发器和系统动作均只读。
- 系统项以摘要内容和“系统预置”标签呈现，不显示可编辑但被禁用的控件。
- 只有允许自定义的功能节点接口开放新增、删除和编辑。
- 设备能力节点的 WORKFLOW/STATE 接口均由系统契约生成，用户只查看，不修改。

### 5.3 允许信号

允许信号改为多选下拉框，选择后以标签形式展示；禁止自由输入字符串。

候选值不得在前端硬编码，由后端协议元数据返回：

- `WORKFLOW` 接口：来源于 `WorkflowNodeSignal`。
- `STATE` 输出接口：来源于 `WorkflowControlSignal`。
- `STATE` 输入接口：来源于 `StatusSignal`。

`SUBFLOW_COMPLETED` 属于子流程调度的系统信号，只在子流程系统接口中展示，不提供给普通功能节点自定义接口选择。系统预置接口保留其契约声明的信号集合。

后端仍校验信号是否包含在目标接口 `allowedSignals` 中，并校验接口类型、方向与信号类别是否匹配。

## 6. 触发器语义与界面

### 6.1 执行语义保持不变

工作流引擎对每个活跃节点单独处理：按 OUT 接口在前、IN 接口在后的顺序遍历接口，再按接口内声明顺序遍历全部触发器。某个触发器在本轮出现有效上升沿时，立即执行该触发器自己的动作；不收集成统一动作列表，也不强制 UPDATE 与 EMIT 的先后顺序。

同一轮中多个触发器同时成立时允许全部执行。前一个触发器产生的生命周期或内部变量变更，由下一轮轮询中的其他触发器观察，从而保持节点内部状态演进清晰可追踪。

### 6.2 条件观测对象

界面将可选对象分为四组：

1. 接口信号：`signalName`，表示当前触发器所在接口的当前信号名。
2. 节点生命周期：`nodeLifecycleState`，值来自 `TASK_STEP.NODE_STATUS`。
3. 内部变量：节点 `internalVariables[].name`，运行值来自 `VARIABLE_SPACE`。
4. 节点计算结果不使用独立的 `expression` 观测对象；触发器直接选择赋值表达式左侧的内部变量。

`payload` 是当前接口信号的完整载荷对象，不适合作为普通标量条件，普通自定义触发器不直接选择它。`payload.stateName` 是设备状态机 `CMD_STATE` 载荷中的状态字段，保留给设备能力节点的系统触发器使用，并以只读中文摘要呈现。后端仍保留点路径解析能力，以兼容系统契约及已存在的合法模型。

条件编辑器根据观测对象自动限制比较符和阈值控件：

- 字符串/枚举：等于、不等于、属于、不属于。
- 数值：等于、不等于、大于、大于等于、小于、小于等于。
- 布尔：等于、不等于。
- 接口信号和生命周期的阈值使用枚举下拉框，不允许自由拼写。

### 6.3 动作编辑

动作继续采用内联的 `WorkflowNodeAction` 格式，并保留节点级 `actions[]` 作为动作能力声明。

#### EMIT

- 发送接口固定为该触发器所绑定的接口，不再让用户重复选择 `targetInterfaceName`。
- 前端保存时自动写入当前接口名称作为 `payload.targetInterfaceName`，保持现有模型格式兼容。
- 只有 `OUT` 接口可选择 `EMIT`。
- `payload.signalName` 从该接口的 `allowedSignals` 中选择。
- 后端编译阶段增加约束：`targetInterfaceName` 必须等于触发器所在接口，且该接口必须为 `OUT`。

#### UPDATE

- `IN`、`OUT` 接口均可使用 `UPDATE`。
- `INTERNAL_VARIABLE`：选择节点内部变量，再使用常量值或 `valueExpression`，二者互斥。
- `NODE_LIFECYCLE`：选择目标生命周期，后端依据节点 `lifecycle.transitions` 校验当前状态到目标状态是否为合法转移；引擎只执行节点动作申请的合法转移，不自行越过节点改变状态。

### 6.4 触发器界面布局

每个自定义触发器使用一块紧凑规则面板，而不是横向超长表单：

```text
触发器 1                                      删除
当  [观测对象] [操作符] [阈值]
则  [动作类型]
    [动作对应的参数区域]
```

- 常用短字段使用短控件，表达式和值输入按需要占用剩余宽度。
- 系统触发器显示为自然语言摘要，例如“当节点生命周期等于 RUNNING 时，从当前接口发送 WF_EXECUTE_START”，不显示禁用表单。
- 校验错误就近显示在具体字段下，不使用只在页面顶部出现的笼统错误。

## 7. 功能节点计算表达式

### 7.1 语义

`expression` 是赋值计算表达式，格式为 `目标内部变量 = 计算式`。目标必须是当前 BRANCH 或 AGGREGATE 节点已经声明的内部变量。引擎在轮询节点时先计算右侧并写入目标变量，再基于更新后的不可变快照遍历接口触发器，因此节点 expression 的计算结果可在同一轮被 condition 观察。

触发器不再暴露名为 `expression` 的临时观测对象。路径判断直接引用 expression 写入后的目标内部变量。

内部变量赋值继续通过 `UPDATE / INTERNAL_VARIABLE` 完成：

- 常量赋值使用 `payload.value`。
- 计算赋值使用 `payload.valueExpression`。

### 7.2 第一版语法

基础计算支持：

- 数值常量。
- 数值型内部变量。
- `+`、`-`、`*`、`/`。
- 一元负号。
- 圆括号。

编辑器中输入 `@` 后弹出当前节点可用的数值型内部变量。选中变量后以带底色的变量令牌显示，保存时转换为后端现有表达式标识符，不把 `@` 写入模型。

删除“求和、求差、乘积、比值”等没有业务价值的模板。编辑器改为提供少量实验室时序函数插入菜单：

- `rate(variable, seconds)`：时间窗口内每秒变化速率。
- `delta(variable, seconds)`：时间窗口内总变化量。
- `avg(variable, seconds)`：时间窗口平均值。
- `max(variable, seconds)`：时间窗口最大值。
- `min(variable, seconds)`：时间窗口最小值。
- `abs(value)`：绝对值，可组合 `rate` 等结果表达稳定性。

时序函数只读取当前任务、当前流程模型、当前节点、当前内部变量的有界历史快照。工作流引擎仍不直接读取设备遥测；设备数据必须先经映射进入节点内部变量。服务重启后历史窗口重新积累，不增加数据库字段。

时序函数历史样本不足时返回“暂不可用”：节点 expression 本轮不覆盖目标变量，依赖该结果的 condition 按不满足处理，节点和任务不因此失败。

### 7.3 校验

前端实时校验：

- 括号是否配对。
- 是否存在未知变量。
- 是否使用非数值变量。
- 赋值左侧是否为已声明的数值内部变量。
- 时序函数名称、参数数量、窗口秒数是否正确。
- 是否出现未支持符号或函数。
- 除数风险只提示，不在设计阶段阻止保存；运行时实际除零仍由引擎报告执行错误。

后端编译阶段使用与运行时相同的词法/语法能力再次校验，拒绝未知变量、非数值变量和未支持函数，避免绕过前端直接提交无效模型。

## 8. 后端元数据、规范化与校验

### 8.1 前端元数据

扩展现有前端 Schema 元数据接口，新增从协议规范提取的枚举集合：

- `workflowNodeSignals`
- `workflowControlSignals`
- `statusSignals`
- 计算表达式支持的操作符与模板定义

前端只消费元数据，不复制协议枚举。

### 8.2 编译校验

在现有工作流编译器原有校验位置补充：

1. EMIT 动作目标接口等于触发器宿主接口。
2. EMIT 只能绑定在 OUT 接口。
3. 信号属于接口 `allowedSignals` 且与接口类型、方向匹配。
4. 自定义触发器不可引用未声明的内部变量。
5. 节点 `expression` 只可用于 BRANCH、AGGREGATE，触发器 condition 不提供名为 `expression` 的对象。
6. `value` 与 `valueExpression` 不得同时存在。
7. `value` 类型与目标内部变量 `dataType` 一致。
8. `valueExpression` 和功能节点 `expression` 通过计算表达式语法与变量类型校验。
9. 生命周期 UPDATE 的目标状态存在，实际执行时还必须命中当前状态对应的 `transitions`。

### 8.3 兼容处理

- 系统契约中合法使用的 `payload.stateName` 保持不变。
- 已有合法 EMIT 动作若目标就是宿主接口，无需迁移。
- 若历史自定义模型存在“触发器绑定接口 A、EMIT 从接口 B 发送”的结构，加载时允许查看，但静态检查明确报错；用户进入编辑并修正后才能保存或发布，不静默改写业务语义。
- 不调整运行中任务快照，不对历史任务执行数据做迁移。

## 9. 错误与状态反馈

- 元数据加载失败时，接口和触发器进入只读状态，并显示“协议元数据加载失败，暂不能修改”，不回退到自由文本输入。
- 流程加载失败时保留当前画布，不先清空再报错。
- 清空画布后提供一次可撤销入口；如果现有撤销栈无法安全覆盖全量清空，则至少保留二次确认和未保存状态提示。
- 静态检查结果定位到具体节点、接口和触发器。
- 编辑按钮切换模式时不触发保存；保存成功后更新当前流程快照和脏状态。

## 10. 测试与验收

### 10.1 前端测试

- 设备库树按类别、模型、实例、能力正确构建和筛选。
- 流程库按启用/草稿分组，点击后进入查看模式。
- 查看模式覆盖新增、删除、拖拽、连线、表单修改等全部写操作。
- 点击编辑后恢复写操作。
- 清空只删除节点和连接，保留名称、描述，且保存前不调用持久化接口。
- 切换设备能力会清空旧参数。
- 系统接口和系统触发器以只读摘要显示。
- 允许信号只能从后端元数据候选中选择。
- IN 接口动作不出现 EMIT，OUT 接口 EMIT 自动使用宿主接口。
- 表达式 `@` 补全、变量令牌、序列化和错误提示正确。

### 10.2 后端测试

- 元数据接口返回三类协议信号枚举。
- EMIT 宿主接口一致性校验。
- 接口方向、类型与信号类别校验。
- 计算表达式合法/非法语法、未知变量和非数值变量校验。
- UPDATE 常量值类型、`value`/`valueExpression` 互斥校验。
- 系统契约模型可正常编译，既有引擎触发器测试保持通过。

### 10.3 视觉验收

- 左侧资源树视觉与设备模型页面侧边栏一致。
- 页面不出现非协议字段的英文装饰文案；仅保留 IN/OUT、WORKFLOW/STATE、EMIT/UPDATE 等规范枚举。
- 控件宽度随信息长度分配，不再统一横向铺满。
- 触发器在常见抽屉宽度下无需横向滚动。
- 节点、连线、画布和选中态使用统一的低饱和蓝灰配色，并保持足够对比度。
