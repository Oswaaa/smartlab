# 工作流删除入口设计

## 目标

在流程设计页面为已持久化流程提供明确的删除入口，复用后端现有删除接口和引用保护规则。

## 交互

- 仅当当前画布已加载数据库流程（`form.id` 存在）时，在顶部操作栏显示红色“删除”按钮。
- 删除按钮与“编辑”操作相邻；无需进入编辑状态即可删除。
- 点击后显示二次确认，内容包含当前流程名称，并说明删除后无法恢复。
- 删除请求执行期间按钮显示加载状态，禁止重复提交。
- 后端拒绝删除时，直接展示后端返回的业务原因，例如流程已被子流程或任务实例引用。

## 删除成功后的状态

- 删除当前流程对应的浏览器本地画布布局。
- 关闭节点或连线详情抽屉并清空选择。
- 重置为空白、可编辑的新流程。
- 刷新左侧流程库。
- 显示“流程已删除”成功提示。

## 技术边界

- 前端服务层新增 `workflowApi.delete(id)`，调用 `DELETE /api/workflow/delete/{id}`。
- 不修改后端删除规则。
- 不增加流程库右键菜单，不处理批量删除。
- 不触碰工作区中与本功能无关的未跟踪文件。

## 验证

- 服务层必须暴露删除请求。
- 页面必须仅为已持久化流程渲染删除入口，并具备确认、加载、错误反馈和删除后重置逻辑。
- 前端完整测试和生产构建必须通过。
