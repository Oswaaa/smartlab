# 工作流接口方向切换设计

## 目标

将流程设计器的“新增接口”改为单一入口，不再要求用户在创建动作中预先选择输入或输出方向。接口创建后，用户在接口详情中选择实际方向。

## 创建规则

- 分支节点、开始节点新增接口时默认使用 `OUT`。
- 聚合节点、结束节点新增接口时默认使用 `IN`。
- 其他功能节点默认使用 `OUT`。
- 新接口名称根据默认方向生成；方向改变后名称不自动改写，避免破坏用户已输入的名称。

## 方向切换规则

- 未建立连线且没有不兼容触发器时，直接切换。
- 已建立连线或存在不兼容触发器时，先提示用户确认。
- 确认后删除涉及该接口的全部工作流接口连线，并清理与新方向不兼容的触发器。
- 用户取消时，接口方向和现有配置保持不变。

方向兼容规则：

- `IN` 接口不得保留 `EMIT` 触发器。
- `OUT` 接口允许 `EMIT` 和 `UPDATE` 触发器。
- 聚合接口切换为 `IN` 时自动补齐一条只读系统计数触发器：收到 `ACTIVE` 后以 `aggregateCount + 1` 更新 `aggregateCount`。
- 聚合接口切换为 `OUT` 时移除该接口的系统计数触发器。

## 聚合节点激活边界

`valueExpression` 只表达 UPDATE 的右值，因此计数动作保持 `targetName: aggregateCount` 与 `valueExpression: aggregateCount + 1`，其完整语义为 `aggregateCount = aggregateCount + 1`。

每个聚合输入接口各自拥有计数触发器，但 `aggregateCount > 0 AND nodeLifecycleState = PENDING -> RUNNING` 只保留在默认系统输入接口上。该条件观察节点全局变量，不依赖宿主接口自身收到信号；只保留一份可以避免同轮多个接口重复申请生命周期转移。

## 验证

- 单一“新增接口”按钮按节点类型使用正确默认方向。
- 聚合节点新增输入接口自动附带计数触发器。
- 普通接口在 `OUT -> IN` 时清理 `EMIT` 触发器。
- 聚合接口在 `IN -> OUT` 时移除系统计数触发器，在 `OUT -> IN` 时补回且不重复。
- 方向切换确认后删除该接口全部连线；取消时不修改任何数据。
- 前端相关单元测试和生产构建通过。
