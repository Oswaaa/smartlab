# 任务设备绑定流程图设计

## 目标

创建任务时以真实流程拓扑作为设备绑定主入口。用户能够从流程上下文中识别设备节点，点击节点后绑定设备实例，同时继续使用后端 `requirements` 返回的 `slotId` 作为唯一绑定标识。

## 数据边界

- `/api/workflow/detail/{id}` 提供节点、接口连接和子流程定义，用于绘制流程图。
- `/api/workflow/{id}/requirements` 提供设备绑定要求，用于确定设备节点是否需要绑定、可绑定的设备模型及最终提交的 `slotId`。
- 前端不得根据节点名称重新生成或猜测绑定槽位。
- 流程节点与绑定要求通过后端已有的 `flowModelId`、`nodeIdRef` 和完整 `slotId` 关联；绑定提交仍为 `{ slotId, deviceInstanceId }`。

## 界面结构

设备实例绑定区域采用左右布局：

- 左侧为只读流程图，显示功能节点、设备能力节点、子流程节点及节点间执行连接。
- 设备节点显示“待绑定”或已绑定实例名称；点击设备节点后进入选中状态。
- 功能节点只提供流程上下文，不打开绑定操作。
- 子流程节点点击后进入对应子流程实例，顶部路径显示当前位置并允许逐级返回。
- 右侧为设备绑定面板，显示节点路径、设备模型、设备能力和兼容设备实例下拉框。
- 顶部显示已绑定、待绑定数量；提供定位下一个未绑定节点的操作。
- 窄屏时右侧面板移动到流程图下方。

## 子流程处理

每个子流程出现位置独立显示和绑定。相同子流程被引用多次时，分别形成不同的导航路径和 `slotId`，不得合并为同一槽位。

主流程图中的子流程节点仅作为入口。进入后绘制该次子流程出现位置内部的真实拓扑；返回上级后保留已经完成的绑定和当前流程图状态。

## 状态与错误

- 未选择流程时不显示绑定流程图。
- 加载流程详情失败时显示明确错误，不退化为猜测节点与槽位。
- 设备节点找不到对应 `requirements` 时标记为“绑定信息异常”，禁止选择实例并阻止创建前检查。
- 非设备节点不会参与绑定完成度统计。
- 所有绑定完成后才允许创建前检查；创建前检查通过后才允许创建任务。

## 测试

- 单元测试验证 `nodeIdRefs` 与 `nodesDef` 的规范化关联。
- 单元测试验证重复子流程形成不同的设备节点 `slotId`。
- 组件结构测试验证使用 Vue Flow、节点点击绑定和子流程导航。
- 回归测试验证创建前检查与正式创建均提交相同的 `slotId` 数据。
- 完整前端测试与生产构建必须通过。
